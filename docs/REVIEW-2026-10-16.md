## Ground rules for the implementing session (do not skip)

- **Versioning:** bump the **patch** in `src/Cardinator/Cardinator.csproj` on every batch/push
  (1.7.6, 1.7.7, …). Minor only for big work agreed with the user; **never the major.** The release
  is automatic from CI — check the run went green and `gh release view v<Version>` exists.
- **Workflow per batch:** implement → tests (each fix verified to fail with the fix reverted) →
  `dotnet test` → docs/screenshots if UI changed → version bump → commit → push.
- **Data safety is the #1 requirement.** Every older file format must keep opening (`JsonCompat`:
  only add optional properties with defaults). Never weaken atomic writes or backups.
- Long commit messages: `commit-msg.tmp` in the repo root, `git commit -F`, then delete it.

**Verification legend:** ✅ = re-checked line-by-line by the coordinating session;
🔶 = verified by the area reviewer (traced or reproduced — re-check the cited lines before editing).
"Found by N" = reported independently by N reviewers.

## Batch A — Data safety → **1.7.6** — ✅ done

### A1. ✅ HIGH — "Export all" / `--renderset` deletes the user's own files named `digits_….png`
- `Services/BatchService.cs:356` — `StaleCardFile = ^\d{3,}_[^\\/]+\.png$`; `RemoveStale` (:361-373)
  deletes every match the export didn't write. Used by `--renderset` (`SetCommands.cs:240`) and the
  window's **All as images…** (`MainWindow.xaml.cs:2158`) into *any folder the user picks*.
- Reproduced: `2024_holiday.png` and `0001_mine.png` in the output folder are deleted. Camera/phone
  names like `20241010_142233.png` in Pictures or Desktop would go. CLI.md promises "other files are
  left alone".
- Fix: keep a manifest (e.g. `.cardinator-export`) of the files each export wrote and only remove
  names listed in the previous manifest. Tightening the regex alone is not enough (dated names still
  match `NNN_slug`).
- Test: `ExportAll(..., wholeSet: true)` into a folder holding `2024_holiday.png` → file survives;
  a card removed from the set between two exports → its old PNG *is* removed.

### A2. ✅ MEDIUM — The window's Save ignores `SetLock`; a command can overwrite a window save
- `SetCommands.cs:136-175, 281-317` hold the lock from load to save; `MainWindow.SaveProject`
  (`MainWindow.xaml.cs:1748-1823`) never takes it (no `SetLock` reference in MainWindow at all).
- Failure: a themed-set script runs `--restyle` (takes the lock, loads); the user saves an edit in the
  window; `--restyle` writes what it loaded. The edit survives only in `backups\`, and the window
  doesn't think anything is unsaved.
- Fix: (1) commands record the file's write time + length at load and refuse to save (exit 1) if it
  changed; (2) the window's Save tries `SetLock.Take` with a short wait and tells the user a command is
  working on the set.
- Test: load in a `--restyle`-shaped flow, rewrite the file externally, run the save step → exit 1,
  external bytes kept.

### A3. ✅ MEDIUM — "Every set gets its own folder" (1.7.5) has three holes — *found by 3*
- **First set goes loose:** `SetFolder.OwnFolderPath` (`SetFolder.cs:113`) keeps the picked path when
  the folder is empty. The first save into a fresh `Documents\Cardinator Sets` writes the set file plus
  `art\ out\ backups\` straight into it; every later set becomes a subfolder *of the first set's
  folder*. Moving/deleting "the first set's folder" takes the whole library. `Review9Tests.cs:250`
  currently asserts the wrong behaviour.
- **Save as nests inside the old set:** the dialog opens in `_projectFolder`
  (`MainWindow.xaml.cs:1758`, `SaveDialogFolder` :1829). Open `Sets\MySet\MySet.cardinator`, Save as
  "MySet v2" → `Sets\MySet\MySet v2\MySet v2.cardinator` — the new version lives inside the old one.
- **Shared sets and Open still use the app folder:** `OpenSharedSet` unpacks into
  `AppPaths.SamplesDir` (:1598) and Open starts there (:1586). That folder sits beside the portable
  exe; replacing the exe folder on update loses edited shared sets. USER_GUIDE.md:363-364 says
  "next to your other sets".
- Fix: nest unless the folder's name already equals the set's name; when the picked folder is itself a
  set folder (contains another `.cardinator`), place the new set beside it; Save-as dialog starts in
  the parent of the current set folder; unpack shared sets into and Open from `AppPaths.NewSetsDir`.
- Tests: `OwnFolderPath(NewSetsDir\First.cardinator)` on an empty folder → `…\First\First.cardinator`;
  `OwnFolderPath(setDir\Other.cardinator)` where `setDir` holds `MySet.cardinator` →
  `parent\Other\Other.cardinator`; a dropped `.zip` unpacks under `NewSetsDir`.

### A4. ✅ MEDIUM — Scryfall outage (5xx) makes `--import` save a set of blank cards
- `ScryfallClient.cs:224-237` — after the retries a 503 throws `ScryfallException` with
  `Unreachable == false`; `BatchService.cs:184-188` counts every card as "not found" (each tried with
  retries), never sets `unreachable`. `RunImport` saves the name-only cards and exits 4. CLI.md: "When
  Scryfall can't be reached, nothing is saved (exit 1)". `--batch`/`--sheet` draw blank cards.
- Fix: 5xx and an exhausted 429 → `unreachable: true`.
- Test: `ScryfallClient.TestHttp` always 503 → `RunImport` returns 1 and writes no file.

### A5. ✅ MEDIUM — `--import` (no `append`) checks "already exists" before taking the lock — *found by 2*
- `SetCommands.cs:112` vs `:136`. Two imports into the same new path both pass; the second waits for
  the lock then overwrites the first (it ends up only in backups). CLI.md: "An existing set is never
  touched".
- Fix: repeat the `File.Exists && !append` check after `TakeLock`.
- Test: hold a `SetLock`, start `RunImport`, create the file, release → exit 2, file unchanged.

### A6. ✅ LOW-MEDIUM — Recovery copies drop a newer version's set-level fields; format version never bumped
- `RecoveryStore.Write` (`RecoveryStore.cs:42-56`) builds a `CardProject` with no `Unknown`, and
  `OpenRecovered` → `LoadProjectFile` clears `_projectUnknown` (`MainWindow.xaml.cs:1629`). Open a
  `formatVersion: 2` set with an unknown field, edit, crash, recover, save → the field is gone and the
  "newer Cardinator" warning no longer shows (reproduced by the reviewer). Card/profile-level unknowns
  survive.
- 🔶 `CurrentFormatVersion` (`CardProject.cs:36`, :87) is still 1 although `halfTemplateName` (1.6.9)
  and `profile.cardBack` (1.7.0) were added — a kept 1.6.9–1.7.3 portable exe opens a 1.7.x set with
  no warning and drops the card back and half frames on save. And a save always stamps 1, even over a
  v2 file.
- Fix: pass `_projectUnknown` (and the loaded format version) through `RecoveryStore.Write`/meta;
  bump `CurrentFormatVersion` to 2 and save `Math.Max(loaded, Current)`. Update the pin in
  `Review8Tests.cs:156-163`.
- Test: newer-version file → `WriteRecovery` → `OpenRecovered` → save → unknown key and version kept.

### A7. 🔶 LOW — Smaller safety items (bundle)
- `IoUtil.AtomicWrite` (:40-56): no `Flush(true)` before the move (power cut can leave an empty set
  file; backups survive); no retry on a sharing violation — likely on OneDrive now that sets default
  to Documents. Write via `FileStream` + `Flush(true)`, retry the move 3–5× ~100 ms on sharing
  violations.
- `SetLock.Take` (:28-38) retries only `IOException`; a delete-pending lock file throws
  `UnauthorizedAccessException` → "Access denied" instead of waiting.
- `OpenRecovered` stamps the disk while the set file is missing (folder moved since the crash), so
  `SaveConflict` returns null and Save recreates the old folder with only the set file. Check for a
  missing folder when the stamp is null.

- **Imports/CLI:** `CliArgs` strictness (unknown flags, missing/empty values, ranges, exit 2); list
