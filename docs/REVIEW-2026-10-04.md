Four parallel reviewers (rendering, UI, data/services, tests+docs); every HIGH and most MEDIUM
findings were then independently re-verified against the source by the coordinating session.

## Ground rules for the implementing session (do not skip)

- **Versioning:** bump `<Version>` in `src/Cardinator/Cardinator.csproj` by the **patch** digit on
  every batch/push (1.4.1, 1.4.2, …). **NEVER bump the major to 2.0 — that is the user's decision
  alone.** A minor bump (1.5.0) only for big work explicitly agreed with the user. The app derives
  its displayed version from the assembly (`App.VersionNumber()`); never hardcode a version string.
- **Workflow per batch** (established with the user): implement → unit tests (TDD where natural) →
  `dotnet test` + coverlet (`--collect:"XPlat Code Coverage"`) → docs/screenshots if UI changed →
  version bump → commit → push. Commit directly to `main`.
- **Data safety is the #1 product requirement:** the user's friend is a real user. Never lose or
  overwrite user data; new versions must always read all old file formats (`JsonCompat` policy:
  only ADD optional properties with defaults; never rename/retype).
- Build: `dotnet build src/Cardinator/Cardinator.csproj -c Debug`. Tests:
  `dotnet test tests/Cardinator.Tests/Cardinator.Tests.csproj`. Headless doc regen: run the exe
  with `--docs` via `Start-Process -Wait` (the GUI exe detaches otherwise).
- PowerShell commit gotcha: run `git commit -m @'…'@` as a **standalone** command (closing `'@` at
  column 0, nothing chained before/after); never write commit-message files inside `.git\`.
- Jacob's personal FMA frames (gitignored `jacob/`) are never committed. Review renders go to
  `C:\temp\fma_jacob\REVIEW`.

**Verification legend:** ✅ = re-verified line-by-line by the coordinating session;
🔶 = verified by the area reviewer (trustworthy but re-check the cited lines before editing).

## Batch A — Data-safety fixes → **1.4.1** (do this first)

### A1. ✅ HIGH — DFC back-face art is not portable: localization/relativization skips `BackFace`
- `src/Cardinator/Services/SetFolder.cs:44-48` (`LocalizeImages` iterates only `c.ArtPath` /
  `c.SetSymbolPath`), `src/Cardinator/Models/CardProject.cs:97-101` (`MakeArtRelative`),
  `:104-108` (`ResolveArt`), and `SetFolder.cs:67-76` (`CountMissingArt`) — none recurse into
  `card.BackFace`.
- Failure: import a real DFC (back art downloads to `CardinatorData\art\…`, absolute path) → Save →
  front art is copied into `<set>\art` and stored relative, the back face's `artPath` stays
  absolute into the app cache. Move/zip/share the set folder (or reinstall): **back art renders
  blank with no warning** (`CountMissingArt` also skips backs). Found independently by two
  reviewers.
- Fix: in all four methods, after processing the card, process `card.BackFace` when non-null
  (exactly one level — the model guarantees no deeper nesting). Consider a small shared helper
  `IEnumerable<CardModel> SelfAndBack(CardModel c)` to avoid four hand-rolled recursions.
- Tests: extend `SetFolderTests` — DFC card with absolute back art → `LocalizeImages` copies it
  into `art\` and rewrites the path; `CardProject` round-trip test — save with back art inside the
  set folder → JSON contains a relative back path → load resolves it absolute; `CountMissingArt`
  counts a missing back.

### A2. ✅ HIGH — Back-face edits bypass dirty tracking, undo, and (for button paths) the preview
- `src/Cardinator/Models/CardModel.cs:137-146` — the `BackFace` setter does not forward the
  child's `PropertyChanged`; `src/Cardinator/MainWindow.xaml.cs:191-196` — `SelectedCard`
  subscribes `OnCardChanged` only on the front card. All `ActiveFace`-routed handlers (`SetArt`
  :1639, `OnClearArt` :1651, mouse pan :1722, wheel zoom :1743, `NudgeArt`, `ZoomArt`,
  `PasteArtAsync`) therefore mutate the back face without `MarkDirty`/`QueueUndoCommit`.
- Failure A (silent data loss): open saved DFC project → Show back → pan/zoom the back art (looks
  fine on screen — drag handlers call `RenderPreviewLive` directly) → title never shows ● → close
  → no save prompt → **the framing is gone**.
- Failure B (stale preview): Show back → Paste/Change art/Clear art → status reports success but
  the preview doesn't refresh (those handlers rely on the PropertyChanged→`_renderTimer` path,
  which never fires for a back).
- Fix (minimal, in MainWindow — keeps the model's event surface unchanged): in the `SelectedCard`
  setter, also detach/attach `OnCardChanged` on `_selectedCard.BackFace`; inside `OnCardChanged`,
  when `e.PropertyName == nameof(CardModel.BackFace)`, re-hook the (new/removed) back face. That
  one change restores dirty + undo + debounced re-render for every back-face path at once.
  (Alternative: forward child PropertyChanged inside `CardModel.BackFace` — more invasive;
  remember to detach the old back's handler to avoid leaks. Prefer the MainWindow fix.)
- Tests: STA `WindowSmokeTests` — flip to back, change `ArtScale` on the back face, assert
  `WindowTitle` gains ● and undo stack grew; model-level test if the model route is chosen.

### A3. ✅ HIGH — A user's imported custom frame.png is deleted and overwritten on one failed decode
- `src/Cardinator/Services/TemplateService.cs:192-193` — `TryLoadFrame` does
  `catch { SafeDelete(framePath); … }` on any decode failure, then attempt 2 hits
  `EnsureFrame`'s no-source branch (`:158-159`) which regenerates a **procedural placeholder over
  the user's only copy**. Both import paths (`TemplateImporter.CreateFromFrame` :26,
  `ImportBundle` :87) set `CustomFrame = true` and never set `FrameSrc`, so frame.png is the only
  copy of the user's art. One transient read/decode error (sync-tool conflict, AV lock, truncated
  write) → permanent loss, silently masked by a generic-looking frame.
- Fix: in `TryLoadFrame`, when `spec.CustomFrame && !CustomFrameComposer.HasSource(spec)`, never
  delete — rename to `frame.png.corrupt-<yyyyMMdd-HHmmss>` (keep the bytes) and return null so the
  template is skipped for this run, or retry without deleting. Delete-and-regenerate stays correct
  for procedural frames (reproducible) and composed frames (FrameSrc is the source of truth).
- Tests: `TemplateServiceTests` — create a custom template dir (CustomFrame, no FrameSrc) with an
  unreadable frame.png → load → assert the original bytes still exist on disk under some name and
  no placeholder overwrote them.

### A4. ✅ HIGH — Restore-a-backup is broken three ways
- `src/Cardinator/MainWindow.xaml.cs:847-876` (`OnRestoreBackup`) + `:783-801`
  (`LoadProjectFile`):
  1. `LoadProjectFile(backupPath)` resolves relative art against the **backup file's own folder**
     (`:788` + `:796`), i.e. `<set>\backups\art\pic.png` — which doesn't exist. Every relative art
     link breaks ("N cards have missing art"), and a subsequent Save re-relativizes the broken
     paths as `backups\art\…` into the project file.
  2. `_projectPath = ""` (`:872`) contradicts the comment "a subsequent Save restores it in
     place": Save becomes an unexpected Save-As dialog (name/folder defaults wrong for a restore).
  3. `LoadProjectFile` swallows its own failures, so when the chosen backup is unreadable,
     `OnRestoreBackup` still blanks `_projectPath` and sets `Dirty = true` on the **intact,
     currently-loaded project** — it loses its save path and shows ● for no reason.
- Fix:
  - In `LoadProjectFile` (or a wrapper used by restore): when the loaded file's directory is named
    `backups` and sits directly under a folder containing the real project, resolve art against
    the **parent** folder. Cleanest: give `LoadProjectFile` an optional `resolveFolder` parameter;
    `OnRestoreBackup` passes `Path.GetDirectoryName(_projectPath)`.
  - Make `LoadProjectFile` return `bool` success. `OnRestoreBackup`: capture
    `var origPath = _projectPath;` before loading; **on success** set `_projectPath = origPath`
    (+ `_projectFolder`, `_projectName` unchanged) and `Dirty = true` so one plain Ctrl+S restores
    in place (which itself backs up the bad version first — the existing flow already guarantees
    that); **on failure** change nothing.
- Tests (the top missing test identified): service-level restore round-trip — save project with
  `<set>\art\pic.png` relative art, copy the file into `<set>\backups\X.<ts>.cardinator`, load it
  the way restore will, assert `File.Exists(card.ArtPath)`. Write it first; it fails today.

### A5. ✅ MEDIUM — Backup pruning can delete a sibling project's backups (prefix collision)
- `src/Cardinator/Services/ProjectBackup.cs:55` — `ListBackups` globs `{name}.*{ext}`; for
  `MySet.cardinator` that also matches backups of `MySet.v2.cardinator`
  (`MySet.v2.<ts>.cardinator`). Two projects in one folder is warned-about but allowed
  (`MainWindow.xaml.cs` ~`:896-903`), so saving MySet prunes the combined pool and can delete
  MySet.v2's safety net; the Restore dialog also lists the wrong project's backups.
- Fix: post-filter the glob with
  `^Regex.Escape(name)\.\d{8}-\d{6}(-\d+)?Regex.Escape(ext)$` on the file name (the `-\d+` tail is
  `UniquePath`'s same-second suffix). Keep the glob for cheap narrowing.
- Tests: `ProjectBackupTests` — create backups for both `MySet` and `MySet.v2` in one folder;
  `ListBackups("MySet.cardinator")` returns only MySet's; `Prune` leaves the sibling's intact.

## Batch C — Renderer correctness → **1.4.3**

### C1. ✅ MEDIUM — Planeswalker/saga/class rows drop the font's shadow outline
- `src/Cardinator/Services/CardRenderer.cs:1581` draws badged-row text with raw `dc.DrawText`;

  `DrawGlyphRun(dc, p.Text, new Point(p.X, p.Y), spec.RulesFont)` in `DrawBadgedRows`.
- Test: render a saga on a full-art template with near-white art; assert darker outline pixels

### C2. ✅ MEDIUM — `ParseClassLevels` crashes the render on a huge level number

### C3. 🔶 MEDIUM — Planeswalker text can run under the starting-loyalty shield

### C4. ✅ MEDIUM — Full-art scrim sized from `TextBox` but text laid out in `EffectiveTextBox`

  raw art past the scrim. Fix: use `spec.EffectiveTextBox` in `DrawScrims`. Test: full-art +
  footer-on-border render → sample a pixel in the extension band is scrimmed.

### C5. ✅ MEDIUM — False "border-thin" pixel error when the footer rides on the border

### C6. 🔶 MEDIUM — `CustomFrameComposer.LoadBitmap` re-introduces the UriSource file-lock bug

## Batch D — UX guards & robustness → **1.4.4**

### D1. 🔶 MEDIUM — Keyboard shortcuts bypass the Busy gate
- `MainWindow.xaml.cs:2007-2018` — Ctrl+N/O/D reach `OnNewProject`/`OnOpenProject`/

- Tests: direct method-level — set `Busy = true`, call `Undo()`, assert no state change (STA).

### D2. 🔶 MEDIUM — Pasted-URL art lands on whichever face is active *after* the download
- `MainWindow.xaml.cs:1809-1883` — `PasteArtAsync` awaits the download then calls `SetArt(path)`,
  which re-reads `ActiveFace`; no Busy guard, so switching card/face mid-download misroutes the

  `SetArt(CardModel face, string path)` overload (OnLookup already models the correct capture
  pattern). Same check for the drag-drop path if it awaits.

### D3. 🔶 MEDIUM — Warn when opening a file written by a NEWER Cardinator
- `CardProject.Load` (CardProject.cs:36-49) ignores `FormatVersion > CurrentFormatVersion`. Old
  builds silently strip fields they don't know (that's how a 1.3 build would eat 1.4 back faces —
  mitigated only by rolling backups). Cheap insurance for the *next* format change: on load, if
  `FormatVersion > CurrentFormatVersion`, surface a warning ("saved by a newer Cardinator — saving
  here may drop newer data") via the existing status/dialog path. Load must still succeed
  (tolerant-read promise). Test: JSON with `formatVersion: 99` loads + flags.

  nulls-everywhere JSON (the JsonCompat tolerance promise).
- `SetPackager.cs:63-64` delete-then-move window → `File.Move(tmp, dest, overwrite: true)`.
- `ImportService.CountNamesAlreadyIn/RemoveNamesAlreadyIn` (ImportService.cs:61-72): also match a
  project card named "Delver of Secrets" against an imported "Delver of Secrets // Insectile

- `CardValidator.KnownSymbol` (CardValidator.cs:27-31): accept `{G/U/P}`-style 2-color Phyrexian
